# Contributing

Thank you for your interest in improving this project!  We follow a few simple guidelines to keep the history clean and the review process smooth.

* **Branch naming** – Use `feature/<short-description>` for new features or `fix/<short-description>` for bug fixes.
* **Commit messages** – Follow [Conventional Commits](https://www.conventionalcommits.org/) so that changelogs can be generated automatically (for example: `feat: add logging to API`).
* **Pull requests** – Link to the corresponding issue, attach any relevant plan or dry‑run outputs, and describe how to roll back the change if something goes wrong.
* **Code style** – Use the existing coding patterns within the repository and run any linters or formatters defined in the Makefile.

We appreciate all contributions, from bug reports and fixes to documentation and examples.
